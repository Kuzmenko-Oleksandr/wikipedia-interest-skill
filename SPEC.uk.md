## 1. Суть завдання і критерії оцінювання

### 1.1 Що просять

Самостійна навичка у форматі [Agent Skills](https://agentskills.io/specification),
яка дає ШІ-агентові змогу відповідати на запитання на кшталт:

- «Порівняй зростання інтересу до інтервального голодування в польській і чеській Вікіпедії за два роки»
- «Чи зростає інтерес до астрономії в українській Вікіпедії і наскільки цьому можна довіряти?»
- «Порівняй інтерес до вивчення англійської в обраних мовних розділах і підготуй звіт»

Результат: графіки + короткий звіт (PDF на одну сторінку), рекомендації, що спираються на
дані, з явними припущеннями й обмеженнями.

### 1.2 Що оцінюють (реконструкція за текстом завдання)

| Вимога з тексту | Як закриваємо |
|---|---|
| `SKILL.md` + власний код, а не лише markdown | Python-пакет `wikitrends`, уся логіка в коді, агент лише викликає CLI |
| Жодних скомпільованих файлів, відтворювані залежності | pip-колеса, `requirements.txt` із закріпленими версіями, `uv.lock`, нуль системних залежностей |
| Усе в директорії навички | Пакет лежить усередині `skills/wikipedia-interest/` |
| Допомагати агентові оцінювати результат і перевіряти висновки | 11 гейтів якості, прапорці, вердикт із закритого словника, MDE, таблиця заборонених тверджень |
| Ефективно виконувати повторні й пов'язані запити | Кеш SQLite, ідемпотентні імена артефактів, інкрементне довантаження |
| Рекомендації спираються на дані, припущення зрозумілі | Блок «Обмеження» з 12 пунктів у кожному звіті, не опційний |
| Зручно й ефективно для агента на дешевій моделі | Один основний виклик CLI, ≤8 викликів інструментів, `SKILL.md` ≤5000 токенів, усі обчислення в скриптах |
| Перевірити повний сценарій на Haiku 4.5 | Eval-набір `claude plugin eval` із прогоном на `claude-haiku-4-5` і ablation-плечем |
| Пояснити, як розвивати далі | Розділ README з чотирма етапами |
| Пояснити, як перевірявся результат ШІ | Розділ README + юніт-тести на синтетичних даних з відомою відповіддю |

### 1.3 Явні не-цілі (пишемо в README, це теж сигнал зрілості)

- Не прогнозування. Навичка описує спостережене вікно й не екстраполює.
- Не оцінка платоспроможного попиту. Перегляди — це проксі уваги.
- Не реальний час. Дані відстають на 1–2 доби.
- Не масовий скринінг тисяч тем у v1 (див. план розвитку).

## 2. Стек і ключові архітектурні рішення

| Рішення | Вибір | Обґрунтування |
|---|---|---|
| Мова | Python 3.12+ | matplotlib закриває графіки + PDF + кирилицю однією залежністю |
| Залежності рантайму | `matplotlib`, `numpy`, `httpx` | 24 МБ коліс, нуль системних пакетів, перевірено на macOS |
| Графіки | matplotlib, бекенд Agg | Єдиний варіант headless + нативний PDF без системних залежностей |
| PDF | `matplotlib.PdfPages` + GridSpec | Нуль додаткових залежностей; звіт на 70% складається з графіків |
| Шрифт | DejaVu Sans із постачання matplotlib | Перевірено: покриває всі символи UA/PL/CZ; файл шрифту в репозиторій не кладемо |
| Кеш | SQLite (stdlib) | Нуль залежностей, атомарність, запити за діапазоном дат |
| CLI | `argparse` (stdlib) | Click не потрібен, економимо залежність |
| Статистика | numpy + `math.erfc` | scipy не потрібен, кожен метод вкладається в кілька десятків рядків |

**Відкинуто, з причинами** (пишемо в README, щоб показати, що вибір свідомий):
- `plotly + kaleido` — з версії 1.0 kaleido не постачає Chrome і потребує системного браузера
- `reportlab` — вбудований шрифт Vera **не має кирилиці** й мовчки малює `■■■■` (перевірено)
- `fpdf2` — кидає виняток на першій кириличній літері (перевірено)
- SVG вручну — впирається в стіну SVG→PDF: cairosvg/rsvg виключені умовами завдання
- PHP — знадобився б саморобний рендерер графіків + mPDF + ручне розв'язання проблеми шрифтів

## 4. Зовнішні API — точна специфікація

Усе в цьому розділі перевірено реальними запитами 2026-09-24.

### 4.1 Хост і обов'язковий User-Agent

```
https://wikimedia.org/api/rest_v1/metrics/...
```

⚠️ `api.wikimedia.org/metrics/...` **не є дзеркалом** — він повертає 301 на сторінку
документації. Якщо йти за редиректами без перевірки типу вмісту, отримаєте HTML замість даних.

User-Agent обов'язковий, у форматі, якого вимагає політика Wikimedia:

```
wikipedia-interest-skill/1.0 (https://github.com/Kuzmenko-Oleksandr/wikipedia-interest-skill) httpx/0.28
```

Типові UA (`python-httpx`, `curl`, `Python-urllib`) **блокуються з 403**, зокрема
як префікс. Надсилати браузерний UA політика забороняє.

### 4.2 Ліміти запитів — головне архітектурне обмеження

Задокументовано: 200 запитів/хв з валідним UA. **Фактично виміряно: ~10 запитів/хв**, тобто
рівень «неідентифікованого клієнта». Ліміт діє **на IP**, а не на UA — у CI і за NAT
«відро» спільне.

Наслідки для реалізації:
- Проєктуємо під 10 запитів/хв. Запити послідовні, не паралельні.
- Повтор на 429 і 503 з експоненційним backoff, дотримуємося `Retry-After`, а коли його
  немає, чекаємо ≥5 с.
- ⚠️ **Тіло відповіді 429 — простий текст, не JSON.** `json.loads` на ньому впаде.
- Кеш обов'язковий, а не «бажаний»: історія переглядів після усталення незмінна.

Бюджет запитів для типового сценарію (3 мови, 2 роки):
`1 (пошук) + 1 (sitelinks) + 3 (статті) + 3 (знаменники) = 8 запитів`. Вкладається
у хвилину. Наступне запитання на тих самих даних коштує **0 запитів**.

### 4.3 Перегляди окремої статті

```
GET /metrics/pageviews/per-article/{project}/{access}/{agent}/{article}/{granularity}/{start}/{end}
```

| Параметр | Значення в нашій навичці | Чому |
|---|---|---|
| `project` | `uk.wikipedia` (без протоколу) | |
| `access` | **`all-access`** | поділ mobile/desktop відображає запитаний URL, а не пристрій, і змінювався з інфраструктурних причин; для трендів непридатний |
| `agent` | **`user`** | виключає ботів і автоматизований трафік |
| `granularity` | лише **`daily`** | monthly мовчки обрізає крайові інтервали |
| `start`/`end` | `YYYYMMDD`, включно | |

Відповідь:
```json
{"items":[{"project":"en.wikipedia","article":"Intermittent_fasting","granularity":"daily",
           "timestamp":"2025090100","access":"all-access","agent":"all-agents","views":628}]}
```

⚠️ `timestamp` завжди має вигляд `YYYYMMDDHH`; кінцеві `00` — заповнювач, а не година.

### 4.4 Агреговані перегляди — знаменник нормалізації

```
GET /metrics/pageviews/aggregate/{project}/{access}/{agent}/daily/{start}/{end}
```

Схема відповіді інша: **немає поля `article`**, інший порядок ключів. Окремий парсер.

**Правило:** зріз знаменника має збігатися зі зрізом чисельника — `all-access` + `user`
в обох. Змішування дає метрику, що дрейфує разом зі змінами у фільтрації ботів.

⚠️ Агрегат включає `Main_Page` (~1,4% трафіку en.wikipedia), `Special:Search` (~0,23%)
і всі не-статейні простори назв. Фільтра за простором назв немає. Ми приймаємо систематичне
заниження частки й пишемо про це в обмеженнях.

### 4.5 Межі даних

| Факт | Значення | Перевірено |
|---|---|---|
| Найраніший день (per-article) | **2015-07-01** | так, 20150625 мовчки повертає дані з 07-01 |
| Найраніший день (aggregate) | **2015-07-01** | так, 2015-05-01 повертає 404 |
| Відставання від реального часу | 1 день станом на 2026-09-24; закладаємо 24–48 год | так |

Реалізація: обрізати `start` до 2015-07-01 з попередженням; `end` за замовчуванням —
`сьогодні − 2 дні`.

Застарілі pagecounts (2007-12 → 2016-08) **не використовуються**: інша методологія, поле
`count` замість `views`, лише агрегат, немає даних за статтями. Склеювання двох рядів —
методологічний розрив, а не тренд.

### 4.6 Коди відповідей

| Код | Що означає тут | Дія |
|---|---|---|
| 200 | Дані хоча б за один день (днів може бути менше, ніж запитано) | |
| 400 | Некоректний параметр або формат дати | Не повторювати, виправити запит |
| 403 | Поганий User-Agent | Не повторювати |
| **404** | **«даних немає»**, а НЕ «статті не існує» | Перевірити існування через Action API |
| 429 | Ліміт запитів. Тіло — простий текст | Backoff |
| 503 | Перевантаження бекенду | Повтор |

⚠️ **404 зливає три різні випадки**: помилка в назві / стаття існує, але не мала
трафіку за період / проєкт не завантажено. Показувати це користувачеві як «статтю не
знайдено» не можна.

### 4.7 Кодування назв — тихе джерело помилок №1

1. Канонічна форма використовує підкреслення: `Intermittent_fasting`
2. Пробіли працюють як `%20`, але **`+` у сегменті шляху не декодується**. Ніколи не використовуйте `+`.
3. Скісна риска має бути `%2F`: `AC%2FDC` → працює, `AC/DC` → 400/404. **Відповідь повертає
   декодоване `AC/DC`** — перед повторним використанням закодуйте знову.
4. Unicode: UTF-8 percent-encoding. `M%C3%BCnchen` → `München` у відповіді.
5. ⚠️ **Перша літера чутлива до регістру; API її НЕ робить великою.**

   ```
   .../Astronomy/...  → ~1500 переглядів/день
   .../astronomy/...  → 1 перегляд, HTTP 200
   ```

   Це тихе тисячократне заниження без жодної помилки. **Назви треба нормалізувати
   через Action API або sitelinks Wikidata. Будувати URL з введення користувача
   заборонено.**

Реалізація: `urllib.parse.quote(title.replace(' ', '_'), safe='')`.

### 4.8 Пропуски в даних

⚠️ **Дні без даних ПРОПУСКАЮТЬСЯ, а не повертаються як 0.** Якщо даних немає за весь
діапазон, увесь запит повертає 404, а не порожній `items[]`.

Відповідь не розрізняє «нуль переглядів», «збій збирання даних» і «статті ще не
існувало». Переіндексація на повний календар з NaN обов'язкова (розділ 7.1). Непряма
перевірка: якщо пропуск є і в агрегаті проєкту, це інцидент збирання, а не властивість
статті.

### 4.9 Перетворення теми на назви статей за мовами

**Основний шлях — 2 запити.**

Крок 1: пошук у цільовій вікі дає канонічну назву й захищає від одруківок.
```
GET https://uk.wikipedia.org/w/api.php
    ?action=query&list=search&srsearch=астрономія&srnamespace=0&srlimit=3
    &format=json&formatversion=2
```
⚠️ `snippet` містить HTML (`<span class="searchmatch">`) — приберіть його перед показом.

Крок 2: назва → sitelinks усіма мовами, один запит.
```
GET https://www.wikidata.org/w/api.php
    ?action=wbgetentities&sites=ukwiki&titles=Астрономія
    &props=sitelinks&normalize=1&format=json
```
```json
{"entities":{"Q333":{"sitelinks":{
  "enwiki":{"site":"enwiki","title":"Astronomy"},
  "dewiki":{"site":"dewiki","title":"Astronomie"},
  "plwiki":{"site":"plwiki","title":"Astronomia"}}}}}
```

Q333 має 318 sitelinks, з них 254 — Вікіпедії.

⚠️ Відповідь **має ключем Q-id, заздалегідь невідомий** — ітеруйте за значеннями,
не індексуйте за ключем.

⚠️ Фільтр «dbname закінчується на `wiki`» ловить зайве: `commonswiki`, `metawiki`,
`wikidatawiki`, `specieswiki`. Перетинайте із sitematrix.

`&sitefilter=plwiki|cswiki` зменшує відповідь, коли мови задано явно.

**Список дійсних проєктів** — одноразовий запит, який можна кешувати:
```
GET https://meta.wikimedia.org/w/api.php?action=sitematrix&smtype=language&format=json
```
⚠️ Верхній рівень — об'єкт із числовими рядковими ключами плюс `count` і `specials`.
⚠️ `"closed":""` позначає закриту вікі — перевіряйте **наявність ключа**; `""` хибне.

**Перевірка існування й перенаправлень:**
```
GET https://uk.wikipedia.org/w/api.php?action=query&titles=...&redirects=1
    &format=json&formatversion=2
```
- `query.redirects[]` з'являється, лише якщо відбувся перехід за перенаправленням
- `query.normalized[]` — саме те виправлення регістру, якого pageviews не робить
- Відсутні сторінки: `"missing":true` з `formatversion=2`

### 4.10 Перенаправлення не сумують перегляди — рішення для v1

⚠️ Перевірено: `Obama` отримує 124–206 переглядів/день **незалежно** від `Barack_Obama`.
Перегляд належить назві в URL, який запитав читач. Метрика на одній канонічній
назві систематично занижує — на 10–30% для тем із поширеними синонімами.

**Рішення v1:** рахуємо канонічну назву. Обмеження явно зазначаємо у звіті.
Додаємо опційний прапорець `--include-redirects`, який збирає перенаправлення через
`prop=redirects&rdlimit=500` і сумує ряди.

**Обґрунтування:** за 10 запитів/хв список перенаправлень для 3 мов коштує ще 3 запити
на списки плюс до N запитів на ряди. За замовчуванням це ламає бюджет.
Як опція — правильно й чесно.

## 5. Контракти CLI

Єдина точка входу: `python -m wikitrends <command>`. Шим `scripts/wikitrends` — для зручності.

### 5.1 Головна команда — `compare`

Закриває 90% сценаріїв **одним викликом**. Це ключове рішення для дешевої моделі:
resolve + завантаження + аналіз + графіки + PDF за один виклик інструмента.

```bash
python -m wikitrends compare \
  --topic "інтервальне голодування" \
  --langs uk,pl,cs \
  --since 2024-01-01 \
  [--until 2026-09-22] \
  [--source-lang uk] \
  [--out-dir ./out] \
  [--no-report] \
  [--include-redirects] \
  [--refresh]
```

Альтернатива, коли назви вже відомі (пропускає перетворення теми, економить 2 запити):
```bash
python -m wikitrends compare --titles uk:Астрономія,pl:Astronomia --since 2024-01-01
```

### 5.2 Допоміжні команди

| Команда | Призначення | Коли агент її викликає |
|---|---|---|
| `resolve --topic X [--langs ...]` | тема → канонічні назви + Q-id + список доступних мов | Користувач не назвав мов; треба запропонувати варіанти |
| `fetch --titles ... --since ...` | лише завантаження в кеш | Рідко; прогрів кешу |
| `analyze --titles ... --since ...` | лише статистика, без зображень | Наступне запитання на вже завантажених даних |
| `report --from-run <slug>` | перебудувати PDF з готового аналізу | Користувач попросив звіт після `analyze` |
| `cache --status` / `--clear` | стан кешу | Діагностика |

### 5.3 Контракт stdout — суворий

**Рівно один рядок JSON у stdout. Усе інше йде в stderr.**

```json
{"ok":true,"schema":1,
 "slug":"cs-pl-uk_intermittent-fasting_20240101-20260922",
 "report_pdf":"/abs/out/<slug>/report.pdf",
 "report_png":"/abs/out/<slug>/report.png",
 "charts":["/abs/.../chart-timeseries.png","/abs/.../chart-normalized.png"],
 "metrics_json":"/abs/.../metrics.json",
 "data_csv":"/abs/.../data.csv",
 "summary":"uk: growing ~+31%/yr (medium confidence); pl: no trend; cs: insufficient data",
 "languages":[
   {"lang":"uk","title":"Інтервальне голодування","verdict":"growing","confidence":"medium",
    "pct_per_year":31.2,"vpm_median":31.7,"reach_median":412,"flags":["no_annual_baseline"]},
   {"lang":"cs","verdict":"insufficient_data","blocking_gate":"G1_low_volume"}],

```

Правила:
- Шляхи **абсолютні**. Робоча директорія агента — не наша.
- `summary` ≤200 символів: дешева модель має змогу відповісти користувачеві, **не
  відкриваючи жодного файлу**.
- Увесь рядок ≤1 КБ. Щоденні дані ніколи не йдуть у stdout — вони лежать у `data.csv`.
- Помилка: `{"ok":false,"schema":1,"error":"...","hint":"..."}`, код виходу 1, теж один рядок.
- `hint` обов'язковий і називає конкретну дію: `"Run resolve --topic X to get the canonical title"`.

### 5.4 Імена артефактів

`<slug>` виводиться **із запиту, а не з часу**:
```
"-".join(sorted(langs)) + "_" + article_slug + "_" + start + "-" + end
```
Те саме запитання → та сама папка → повторний запуск ідемпотентний, без смітника з часовими мітками.
Імена файлів усередині фіксовані й нудні: `report.pdf`, `chart-timeseries.png`.
Моделі не доводиться розбирати ім'я, щоб знайти звіт.

## 6. Конвеєр обробки

Порядок етапів суворий; кожен етап споживає вихід попереднього.

```
0. resolve          тема → канонічні назви (Action API + Wikidata)
1. fetch            HTTP + кеш → сирі items[]
2. reindex          повний календар, NaN для пропусків
3. gates            11 перевірок якості → можлива жорстка зупинка
4. normalize        знаменник, згладжений 7-денною медіаною → перегляди на мільйон
5. spikes           ковзна медіана + MAD → маска сплесків, список подій
6. seasonality      індекси днів тижня й місяців → десезоналізований ряд
7. weekly           тижневі медіани за ≥5 спостережених днів
8. trend            Theil–Sen + Mann–Kendall, ДВІЧІ: зі сплесками і без них
9. changepoint      Pettitt + сканування величини сходинки
10. verdict         прапорці → вердикт → рівень довіри
11. render          графіки
12. report          PDF на одну сторінку
```

Гейти (3) виконуються **до** оцінювання. Ряд, що не пройшов гейт, отримує відмову, а не
число з низькою довірою.

## 7. Обробка рядів і статистика

Повні формули, реалізації на numpy і числові приклади для самоперевірки — у
`references/methodology.md`. Цей розділ містить контракт і рішення.

### 7.1 Переіндексація на календар

1. `dates = np.arange(start, end+1d, dtype='datetime64[D]')` — повний календар
2. `y = np.full(n, np.nan)`, значення з API ставляться на позиції своїх дат
3. `t = (dates - dates[0]).astype(float)` — **справжній індекс дня**
4. ⚠️ Ніколи не перенумеровуйте `t` у `0..k` після викидання днів — нахил мовчки
   змінить масштаб
5. `0` з API — справжній нуль і лишається `0.0`; це не те саме, що NaN

### 7.2 Тренд

**Рахується на тижневих медіанах десезоналізованого ряду, очищеного від сплесків.**

Обґрунтування: Mann–Kendall вимагає незалежних спостережень. Щоденні перегляди мають
автокореляцію 0,5–0,9. На щоденних даних p-value занижується на порядки,
і плаский ряд стає «значуще зростаючим». Тижнева медіана механічно прибирає тижневий цикл
і скорочує n з ~1095 до ~156, близько до ефективного розміру вибірки.

Вимоги: тиждень дійсний за ≥5 спостережених днів; тест запускається за ≥26 дійсних тижнів.

- **Theil–Sen**: `β = median{(y_j - y_i)/(t_j - t_i)}` за всіма парами `i<j`
- **Mann–Kendall**: `S = Σ sgn(y_j - y_i)`, дисперсія **з поправкою на зв'язки**
  (статті з малим трафіком мають десятки днів з однаковим значенням — без поправки
  тест поводиться неправильно), нормальне наближення **з поправкою на неперервність** (`S∓1`)
- **p-value без scipy**: `p = math.erfc(|Z| / sqrt(2))` — stdlib, повна подвійна точність
- **Довірчий інтервал нахилу** — з порядкових статистик попарних нахилів, розподіл не потрібен
- **Діагностика**: автокореляція залишків з лагом 1; за `ρ > 0.3` поріг значущості
  посилюється з 0,05 до 0,01

**Два відсотки зростання, обидва у виході:**
- лінійний: `100 × β × 365.25 / level_at_midpoint` (знаменник — підігнане значення
  в середині вікна, а не перший день і не середнє)
- **логарифмічний (головний)**: Theil–Sen на `log1p(y)`, далі `100(e^(365.25b) − 1)`.
  Не залежить від масштабу → **єдиний коректний для порівняння мов**

**Жорсткі правила формулювань:**
- Вікно <365 днів — не переводити в річний темп узагалі
- Довірчий інтервал накриває нуль — відсоток не йде в заголовок
- Довжина вікна називається в тому самому реченні, що й відсоток
- Екстраполяція заборонена

### 7.3 Нормалізація

`vpm = 1e6 × y / D_smoothed`, де `D` — агрегат розділу, згладжений **центрованою
7-денною медіаною** (розділ має власний тижневий цикл і власні дні збоїв; незгладжений
знаменник вносить шум розділу в кожну статтю).

Зріз знаменника має збігатися зі зрізом чисельника. Якщо в знаменнику бракує понад 5%
днів, нормалізовані висновки пригнічуються.

**Розбіжність між сирим і нормалізованим трендом — це знахідка, а не завада:**

| сирий | vpm | Висновок |
|---|---|---|
| ↑ | ↑ | Справжнє зростання інтересу |
| ↑ | плаский | Виріс увесь розділ, а тема лише не відстала. **Зростання інтересу стверджувати не можна** |
| ↑ | ↓ | Розділ ріс швидше за тему; відносний інтерес падає |
| плаский | ↑ | Розділ скорочується; тема тримає рівень і здобуває частку |

### 7.4 Сплески

Центрована ковзна медіана за 15 днів (два повні вікенди) + MAD з константою 1,4826.
Поріг `z > 5.0` — сплеск, `3.5 < z ≤ 5.0` — підвищення, `z < −5.0` — провал.

⚠️ Нижня межа `σ_min = max(1.0, 0.05 × median(y))` обов'язкова: ряди з малим трафіком часто мають
MAD рівно 0, і без межі будь-яке коливання дає `z = ∞`.

Сплески групуються в події (проміжки ≤3 днів зливаються, хвіст спаду відстежується,
доки `z<2` два дні поспіль, але не довше ніж +14 днів після піку).

**Тренд перераховується на очищеному ряді й порівнюється з вихідним:**

| Умова | Вердикт |
|---|---|
| той самий знак, `p_clean < 0.05`, `|β_clean| ≥ 0.5|β_all|` | стійка зміна рівня |
| `p_all < 0.05`, але `p_clean ≥ 0.05` | **зростання, спричинене подіями** |
| обидва значущі, але `|β_clean| < 0.5|β_all|` | справжнє, але роздуте подіями; у заголовку `β_clean` |
| знак змінився | хибний, тренд не стверджується |

### 7.5 Зсув рівня

Тест Петтітта (непараметричний, ранговий, ~15 рядків) + сканування величини сходинки для
розміру ефекту. Моделі порівнюються за медіанним абсолютним залишком із запасом 10% на
користь простішої (модель сходинки має на один параметр більше).

Навіщо: стрибок трафіку через зміну перенаправлення, посилання з головної сторінки чи зміну
видачі Google — це не зростання інтересу. З вердиктом «зсув рівня» річний відсоток зростання
**пригнічується**, бо він описує плавне зростання, якого не було.

### 7.6 Гейти якості

| # | Гейт | Поріг | Серйозність |
|---|---|---|---|
| G1 | Мінімальний обсяг | медіана <10/день → зупинка; 10–49 → лише напрямок | зупинка / погіршення |
| G2 | Мінімум точок | <60 спостережених днів | зупинка |
| G3 | Вікно | <180 днів → зупинка; <365 → без переведення в річний темп | зупинка / погіршення |
| G4 | Вікно для сезонності | <730 днів → річна сезонність недоступна | погіршення |
| G5 | Частка пропусків | >10% попередження, >25% зупинка | попередження / зупинка |
| G6 | Довжина пропуску | >14 днів поспіль | зупинка |
| G7 | **Обвал наприкінці** | див. нижче | зупинка |
| G8 | Пізній початок | перший день >30 днів після початку вікна | погіршення |
| G9 | Нулі | >20% спостережених днів — нульові | погіршення |
| G10 | Якість знаменника | >5% пропусків | погіршення (лише vpm) |
| G11 | Узгодженість зрізу | будь-яка розбіжність agent/access | зупинка (лише vpm) |

**G7 — найважливіший.** Статтю перейменували, трафік перейшов на нову назву, а
старий ряд згасає. Якщо читати наївно, це виглядає як «інтерес упав на 95%».

Правило: `prior = median(days −120..−30)`, `recent = median(last 30 days)`.
Спрацьовує, коли `prior ≥ 50 and recent < 0.05 × prior`, або коли останні ≥7 днів нульові
чи NaN за `prior ≥ 20`. Дзеркальна перевірка на «стрибок на початку» — стаття могла бути
ціллю перейменування, і «зростання» успадковане.

Коли гейт спрацьовує, навичка **повторно перевіряє назву** через `action=query&redirects=1`:
якщо з'являється `redirects[]`, сторінку перенесено — перейти до нової назви
й завантажити знову.

Кожен гейт має готовий текст попередження англійською — він дослівно потрапляє і в JSON,
і в PDF. Тексти — у `references/methodology.md`.

### 7.7 Вердикт

**Не числова оцінка.** Одне число 0–100 приховує, яке саме припущення порушено, і
підштовхує порівнювати ряди, що провалилися з різних причин.

Натомість: набір булевих прапорців + вердикт із закритого словника + три рівні довіри.

Словник вердиктів (перемагає перший збіг):
`insufficient_data` → `series_discontinuity` → `level_shift_up/down` →
`growing_event_driven/declining_event_driven` → `growing/declining` → `stable` →
`no_detectable_trend`

Довіра: починається з `high`; кожна з цих умов (коротке вікно, малий обсяг, пропуски,
немає річної бази, автокореляція, нулі, підозра на сезонність, розбіжність сирого й vpm,
кілька точок зміни, роздування подіями) знижує її на один щабель.

**MDE для нульового результату.** Замість «тренду немає» вихід каже:
«тренд не виявлено; з таким обсягом даних ми помітили б лише зміну,
більшу за ±9,4%/рік». Це перетворює порожню відповідь на змістовну і, мабуть, є
найціннішим рядком звіту.

### 7.8 Таблиця заборонених тверджень

Реалізовано як перевірку у `verdict.py` і як текст у шаблоні звіту.

| Заборонено | Дозволена заміна |
|---|---|
| «X людей цікавляться Y» | «стаття отримала N переглядів/день» |
| «Попит на Y зростає» | «перегляди статей про Y зросли на ~X%/рік за це вікно» |
| «Y досягне N до <дата>» | Нічого. **Жодних прогнозів.** |
| «Тренду немає» (з p ≥ 0,05) | «тренд не виявлено; менше ніж ±MDE%/рік ми б не побачили» |
| «Z спричинило зростання» | «зростання збігається з <подія> <дата>; причинність не встановлено» |
| «Мова A цікавиться більше, ніж B» (із сирих переглядів) | «A має в N разів більше переглядів; на мільйон переглядів розділу A/B = r» |
| Будь-який відсоток за `low_volume` або вікна <365 днів | Лише напрямок |

### 7.9 Порівняння мов

Три числа на мову, кожне відповідає на своє запитання:
- **Охоплення** — медіана сирих переглядів: масштаб аудиторії
- **Проникнення** — медіана vpm: частка уваги розділу, порівнянна між мовами
- **Імпульс** — `pct_per_year_log` на ряді vpm: напрямок, порівнянний між розмірами

**Ранжуємо за проникненням, нічиї розв'язуємо за охопленням, імпульс — як примітка.
Єдиної змішаної оцінки немає** — компроміс між охопленням і щільністю інтересу —
бізнесове рішення, а не статистичне.

**Яруси замість позицій.** Кожна медіана отримує довірчий інтервал з порядкових статистик
(на тижневих значеннях, інакше інтервал оптимістично вузький через автокореляцію).
Мови з інтервалами, що перекриваються, потрапляють в один ярус: «Ярус 1: uk, pl, cs —
статистично нерозрізненні» замість хибних 1/2/3.

⚠️ Мова, що не пройшла гейт, позначається `insufficient_data` і **не ставиться останньою
в рейтингу**. Мовчки поставити такий ряд унизу — найімовірніший спосіб
ухвалити хибне бізнесове рішення: це виглядає як «інтересу немає», а означає «даних немає».

⚠️ Вікна порівнюваних мов мають збігатися. Перетніть їх і перерахуйте на спільному вікні.

## 8. Кеш

SQLite, файл `~/.cache/wikipedia-interest/cache.db` (перевизначається через `--cache-dir`).

```sql
CREATE TABLE pageviews (
  project TEXT, article TEXT, access TEXT, agent TEXT, day TEXT, views INTEGER,
  PRIMARY KEY (project, article, access, agent, day));

CREATE TABLE aggregate (
  project TEXT, access TEXT, agent TEXT, day TEXT, views INTEGER,
  PRIMARY KEY (project, access, agent, day));

CREATE TABLE coverage (             -- які діапазони справді запитувалися
  kind TEXT, key TEXT, start TEXT, end TEXT, fetched_at TEXT,
  PRIMARY KEY (kind, key, start, end));

CREATE TABLE resolve (              -- тема → sitelinks
  source_lang TEXT, query TEXT, qid TEXT, sitelinks_json TEXT, fetched_at TEXT,
  PRIMARY KEY (source_lang, query));

CREATE TABLE sitematrix (json TEXT, fetched_at TEXT);
```

**Таблиця `coverage` обов'язкова**, бо відсутній рядок `pageviews` за день
не відрізнити від «цей день ніколи не запитували». Без неї кеш вічно
перезапитував би дні зі справжнім нулем.

Політика:
- Дані, старші за 3 дні, вважаються усталеними й ніколи не перезапитуються
- Останні 3 дні перезапитуються, якщо запис старший за добу
- `resolve` і `sitematrix` — TTL 30 днів
- `--refresh` обходить кеш для поточного запиту
- Записи пакетуються в одну транзакцію

**Це відповідь на вимогу «ефективно виконувати повторні й пов'язані запити»:**
запитання «а тепер те саме, але чеською» завантажує мережею лише чеський ряд і чеський
знаменник — 2 запити замість 8.

Okabe–Ito, 8 кольорів, розрізнювані за всіх трьох типів дальтонізму:
`#0072B2 #D55E00 #009E73 #CC79A7 #E69F00 #56B4E9 #F0E442 #000000`

Понад 8 рядів — дев'ятий колір не додаємо; переходимо на small multiples.

```python
"font.family": "DejaVu Sans",     # explicit, so a user matplotlibrc cannot override it
"pdf.fonttype": 42,               # TrueType subset, text stays extractable
"axes.prop_cycle": cycler(color=OKABE_ITO),
"legend.frameon": False,
"axes.spines.top": False, "axes.spines.right": False,
```

### 9.3 Графіки

**C1 — щоденна динаміка (на всю ширину, найвища панель).** Одна лінія на мову.
Сирі значення тонкі й напівпрозорі (`lw=0.6, alpha=0.35`), поверх — 7-денне згладжування
(`lw=1.6`, той самий колір). Пара тонка/товста передає співвідношення шуму й тренду без
другої панелі. Сплески — порожні кола; найбільший отримує виноску з датою і
кратністю.

**C2 — порівняння vpm (половина ширини).** Сам нормалізований ряд, а не індекс до
базового періоду. ⚠️ Агент рендерингу пропонував нормалізувати до середнього за перші 14 днів —
це інша величина, що відповідає на інше запитання. Канонічна нормалізація тут одна:
на мільйон переглядів розділу.

**C3 — рейтинг (половина ширини).** `barh`, а не `bar`: підписи мов довгі, а горизонтальні
смуги дають їм місце без повороту.

Вісь дат: `MonthLocator` + `DateFormatter("%b %Y")`, дрібні поділки на понеділках.
⚠️ Передавайте `datetime.date` напряму, а не заздалегідь відформатовані рядки — інакше локатор
не працює. Локаль не чіпайте: вісь, залежна від локалі, ламає відтворюваність.

⚠️ Графіки **не виявляють сплески** — вони отримують готову маску зі `stats.py`.
Два незалежні детектори з різними порогами дали б графік, що суперечить тексту.

### 9.4 PDF на одну сторінку

`matplotlib.PdfPages` + `GridSpec`, A4 книжкова `(8.27, 11.69)`.

Згори донизу: заголовок + запитання користувача → C1 → C2 і C3 поруч → таблиця метрик
(`ax.table`) → «Висновки» → «Припущення й обмеження».

```python
with PdfPages(path, metadata={
    "Title": title, "Author": "wikitrends", "Subject": question,
    "Creator": "wikitrends", "Producer": "matplotlib",
    "CreationDate": None,        # ← the one line that makes the PDF reproducible
}) as pp:
    pp.savefig(fig)
```

⚠️ Не використовуйте `bbox_inches="tight"` для сторінки звіту — розмір сторінки став би
функцією довжини тексту, і A4 перестав би бути A4.

⚠️ Переносьте текст через `textwrap.fill` заздалегідь: `fig.text` не вміє переносити рядки.
Якщо блок висновків не вміщається у своє місце, обріжте його трикрапкою й зафіксуйте
це в JSON. **Звіт на дві сторінки — порушення специфікації, а не м'яка деградація.**

### 9.5 Кирилиця

Ризик підтверджено експериментально: reportlab із Helvetica мовчки малює `■■■■`, шрифт Vera,
що йде з reportlab, кирилиці не має взагалі; fpdf2 кидає виняток.

matplotlib постачається з DejaVu Sans — покриття всіх 65 символів тестового рядка

### 9.6 Відтворюваність

1. `figsize` і `dpi` зафіксовано в коді
2. `CreationDate: None` у PDF, `metadata={"Software": None}` у PNG (інакше

## 11. Тестування

### 11.1 Модульні тести

**`test_stats.py` — синтетичні дані з відомою відповіддю.** Це відповідь на вимогу
«пояснити, як ви перевіряли результат роботи ШІ-інструментів»:
- ряд із точно заданим лінійним трендом → перевірити, що Theil–Sen його відновлює
- плаский ряд + шум → `no_detectable_trend`, а p-value рівномірне на [0,1]
- ряд з одним вставленим сплеском → `growing_event_driven`, `p_clean` втрачає значущість
- ряд зі сходинкою → `level_shift`, а не «зростання на X%/рік»
- приклади, пораховані вручну з `methodology.md` (S = −1, Var(S) = 7.667, Z = 0 тощо) —
  якщо код дає `Z = −0.361`, забули поправку на неперервність; якщо `Var = 8.667`,
  забули поправку на зв'язки

**`test_series.py`** — reindex: пропущені дні стають NaN, справжні нулі лишаються
нулями, `t` не перенумеровується.

**`test_gates.py`** — кожен з 11 гейтів спрацьовує на своїй фікстурі й не спрацьовує
на сусідній.

**`test_render.py`** — п'ять рівнів без візуального порівняння:
1. **Головний тест:** перетворити попередження matplotlib «гліфа немає у шрифті» на помилку й
   зібрати звіт на рядку із символами UA/PL/CZ. Перевірено, що тест справді
   спрацьовує — японський текст його ламає
2. Структура PDF через pypdf: рівно одна сторінка, MediaBox = A4 (595×842),
   немає `/CreationDate`, слова `Вікіпедія`, `Łódź`, `Řehoř`, `Limitations` витягуються як
   текст. Одна перевірка ловить «тофу»-квадрати, відсутню ToUnicode і випадкову растеризацію
   одночасно
3. Побайтовий детермінізм: два запуски → `a.read_bytes() == b.read_bytes()`
4. PNG не порожній: `std > 10`, частка «чорнила» в межах 2–60%
5. Контракт CLI: рівно один перенос рядка в stdout, кожен шлях абсолютний та існує,
   `summary` ≤200 символів

**CI:** `ubuntu-latest` **без встановлених шрифтів і з вимкненим `DISPLAY`**,
`MPLBACKEND=Agg`, `MPLCONFIGDIR=$RUNNER_TEMP/mpl`. Якщо тести там проходять, історія з вбудованим
шрифтом доведена, а не припущена. Плюс рядок матриці на `macos-latest`.

**Офлайн-фікстури.** Тести не ходять у мережу: `--offline-fixture` підміняє HTTP-шар
записаними відповідями. Інакше CI впирався б у ліміт 10 запитів/хв.

### 11.2 Eval на Haiku — виконує вимогу завдання

Використовуємо **`claude plugin eval`** (Claude Code v2.1.269+) — штатний харнес, створений саме
для цього. Чому він, а не власний скрипт: кожен кейс проганяється **у двох гілках — з навичкою і
без неї** — і показує Δ. Якщо Δ≈0, навичка декоративна, і рецензент
бачить це виміряним, а не заявленим.

П'ять кейсів:

| Кейс | Перевіряє |
|---|---|
| `growth-single-lang` | «Is interest in astronomy growing in the Ukrainian Wikipedia?» — базовий шлях |
| `compare-two-langs` | порівняння pl/cs за два роки + PDF |
| `spike-driven` | Тема з одним великим новинним сплеском → агент має сказати «зростання, спричинене подіями» |
| `insufficient-data` | Стаття з малим трафіком → агент має відмовити, а не дати число |
| `negative-should-not-trigger` | Запитання не про Вікіпедію → навичка **не має** спрацювати |

```bash
# quick iteration during development
claude plugin eval . --case growth-single-lang --runs 1 --ablation none \
  --model claude-haiku-4-5

# the full run that goes into the README
claude plugin eval . --model claude-haiku-4-5 --judge-model claude-sonnet-5 --runs 5

# gate in CI
claude plugin eval . --trust-plugin --json results.json --threshold 0.8 \
  --model claude-haiku-4-5 --judge-model claude-sonnet-5 --no-publish --max-cost-usd 20
```

Суддя має бути сильнішим за модель, що тестується: малий суддя позначає правильні, але
інакше відформатовані відповіді як хибні й дає хибнонегативну Δ.

## 13. План ітеративного розвитку (розділ README)

**Етап 1 — від статті до теми.** Сьогодні тема = одна стаття на мову. Насправді
інтерес розподілений між багатьма статтями, плюс перенаправлення. Наступний крок: набір статей на тему
(через категорії Wikidata і `prop=redirects`), сумовані ряди і явно зафіксований,
версіонований склад набору.

**Етап 2 — масштаб.** SQLite → Parquet/DuckDB, пакетний режим для сотень тем, дозавантаження
історії з [дампів](https://dumps.wikimedia.org/other/pageviews/) замість API
(API не призначений для масової історії при 10 запитах/хв), паралелізм,
що поважає ліміт.

**Етап 3 — більше сигналів.** Unique devices як друга думка щодо переглядів
(ендпоінт `/metrics/unique-devices/`, лише на рівні проєкту). Перегляди за країнами —
щоб відокремити «інтерес у країні» від «інтересу мовою», а це не одне й те саме
для рішення про локалізацію. Звірка із зовнішніми джерелами (Google Trends, App Store)
як валідація, а не заміна.

**Етап 4 — перевірка висновків.** Бектест: взяти рішення, які навичка
рекомендувала б два роки тому, і порівняти з тим, що сталося. Лише так можна дізнатися,
чи передбачає зростання переглядів реальний попит — сьогодні це припущення, а не знання.

## 15. Розв'язані суперечності між напрямами дослідження

Зафіксовано, щоб вони не спливли знову під час реалізації.

1. **Виявлення сплесків.** Агент рендерингу запропонував власне (`0.6745·(y−med)/MAD`,
   поріг 3.0, глобальне вікно); агент статистики — ковзне вікно 15 днів,
   поріг 5.0, нижню межу `σ_min`. **Прийнято версію статистики.** Графік нічого
   не виявляє; він малює маску, яку дає `stats.py`.

2. **Нормалізація на графіку C2.** Рендерер запропонував індекс до середнього за перші
   14 днів, статистик — vpm на мільйон переглядів розділу. Це **різні величини**.
   **vpm канонічний**: на графіку, в таблиці та у вердикті. Індекс до бази
   можна додати окремою панеллю, але не замість.

3. **Найраніша межа даних.** Документація Wikimedia каже «з травня 2015»,
   довідник AQS — «з 1 липня 2015». Перевірено запитами: **2015-07-01 для обох рядів**;
   травень–червень повертають 404. Код обрізає до 2015-07-01.

4. **Ліміт запитів.** Задокументовано 200/хв, виміряно ~10/хв.
   **Проєктуємо під 10/хв.**

5. **Формат eval.** Є також `evals/evals.json` від плагіна `skill-creator` —

## 17. Домовленості щодо коду

- **ООП + SOLID + чистий код** — обов'язково:
  - SRP: один клас — одна відповідальність (`PageviewsApi` ходить у мережу, `PageviewCache` зберігає, `CachedPageviews` вирішує, що взяти з кешу)
  - OCP/DIP: залежності передаються в конструктор і типізуються через `typing.Protocol`; кеш обгортає API як декоратор, не знаючи його реалізації
  - LSP/ISP: протоколи вузькі (`PageviewSource` має два методи), тестові фейки підставляються без моків
  - Value objects — `@dataclass(frozen=True, slots=True)`
  - Чиста математика (Theil–Sen, Mann–Kendall) — функції модуля за фасадним класом `TrendAnalyzer`: загортати формулу в клас заради класу — це не чистий код
  - Жодних спекулятивних абстракцій: інтерфейс з'являється, лише якщо має другу реалізацію або тестовий фейк
- **PEP 8** — стиль; форматування й лінтинг через `ruff` (`ruff format` + `ruff check`),
  конфіг у `pyproject.toml`, довжина рядка 100
- **PEP 257** — docstrings: один рядок для простих функцій; для публічних функцій
  з неочевидним контрактом — короткий опис + `Args`/`Returns` (Google style)
- **PEP 484** — анотації типів у кожній публічній функції; `from __future__ import annotations`
- Коментарі — **лише англійською, короткі, в один рядок**, і лише там, де код
  не може сказати сам (чому, а не що). Доречний приклад:
  `# API omits empty days instead of returning 0`
- Жодних закоментованих блоків коду, жодних `TODO` без причини
- Імена: `snake_case` для функцій і модулів, `PascalCase` для класів, `UPPER_CASE` для констант
- Порогові й магічні числа — іменовані константи на початку модуля
- Помилки: власні винятки (`WikitrendsError` і підкласи) з полем `hint`;
  CLI їх перехоплює й друкує JSON-помилку; голий `except:` заборонено
- Логи й прогрес — `logging` у stderr; `print` лише для фінального рядка JSON
