# wikipedia-interest

[English](README.md) | **Українська**

[Agent Skill](https://agentskills.io/specification) (навичка для ШІ-агента), яка відповідає
на запитання на кшталт

- «Порівняй зростання інтересу до інтервального голодування в польській і чеській Вікіпедії за два роки.»
- «Чи зростає інтерес до астрономії в українській Вікіпедії і наскільки цьому можна вірити?»
- «Які мовні розділи приділяють найбільше уваги вивченню англійської? Підготуй звіт.»

за даними переглядів Wikimedia. Один виклик CLI знаходить статтю кожною мовою, завантажує
щоденні перегляди, проганяє перевірки якості й робастну статистику тренду та малює графіки
і PDF на одну сторінку. Агент отримує один рядок JSON із вердиктом із закритого словника,
рівнем довіри й числами, які можна цитувати, тож навіть мала модель відповідає, не
відкриваючи жодного файлу.

Навичка лежить у [`skills/wikipedia-interest/`](skills/wikipedia-interest/):
[`SKILL.md`](skills/wikipedia-interest/SKILL.md) для агента, Python-пакет `wikitrends` з
усією логікою, `references/` з подробицями, які агент читає лише за потреби.

## Швидкий старт: питайте звичайними словами

Програмувати не треба. Ви пишете запитання, Claude сам завантажує дані, рахує і відповідає,
а також робить PDF-звіт.

### Що потрібно (один раз)

1. **Claude Code**: застосунок для комп'ютера або команда `claude` у терміналі, з
   виконаним входом: <https://claude.com/claude-code>. Codex та інші агенти теж підходять,
   див. [Інші агенти](#інші-агенти).
2. **Python 3.12 або новіший.** У терміналі введіть `python3.12 --version`, потім
   `python3.13 --version`. Якщо хоч одна команда показала версію, усе готово. Якщо обидві
   пишуть «command not found», встановіть Python з <https://www.python.org/downloads/>. На
   Mac вбудований `python3` має версію 3.9: це нормально, він просто не використовується.
3. **Інтернет.** Дані беруться з wikimedia.org.

### Кроки

1. **Завантажте проєкт.** У терміналі:

   ```bash
   git clone https://github.com/Kuzmenko-Oleksandr/wikipedia-interest-skill.git
   ```

   Або без git: на сторінці GitHub натисніть **Code → Download ZIP** і розпакуйте архів;
   тоді папка називається `wikipedia-interest-skill-main`.
2. **Відкрийте папку в Claude Code.** У терміналі: `cd wikipedia-interest-skill`, потім
   `claude`. У застосунку: вкладка Code, далі оберіть папку `wikipedia-interest-skill`.
   Нічого не треба встановлювати як плагін: Claude Code сам знаходить навичку в папці.
3. **Напишіть запитання** звичайними словами, будь-якою мовою, наприклад:

   > Підтягни перегляди Вікіпедії про астрономію в українському і польському розділах за
   > останні два роки і скажи, чи зростає інтерес.

4. **Дозвольте команди.** Claude питає дозволу, перш ніж щось запустити: відповідайте
   **Yes** або **Allow**. Лише першого разу він повідомить, що бракує залежностей, і
   попросить запустити команду, яка створює `.venv` і встановлює їх. Дозвольте. Далі кожне
   запитання запускається одразу.
5. **Прочитайте відповідь.** Вона приходить мовою вашого запитання і завжди містить:
   - по одному реченню на мову: що сталося, за які дати і наскільки це надійно (high,
     medium чи low, тобто висока, середня чи низька довіра);
   - яка мова отримує найбільше уваги, якщо мов дві чи більше;
   - де лежить PDF-звіт;
   - рядок «Limitations:» (обмеження): чого ці дані сказати не можуть.
6. **Відкрийте звіт.** Він у папці `out/` проєкту:
   `out/<мови>_<тема>_<дати>/report.pdf`, поруч із графіками (PNG) і щоденними числами
   (CSV).

Одне запитання триває від 15 до 45 секунд, перше, зі встановленням, менше хвилини.
Перевірено на найменшій моделі, Claude Haiku 4.5; більші моделі теж працюють.

### Що можна запитати

- «Порівняй зростання інтересу до інтервального голодування в польській і чеській
  Вікіпедії за два роки.»
- «Чи зростає інтерес до астрономії в українській Вікіпедії і наскільки цьому можна вірити?»
- «Які мовні розділи приділяють найбільше уваги вивченню англійської? Підготуй звіт.»
- «Ми локалізуємо курс про зміну клімату. Яку мову робити першою: німецьку, французьку чи
  польську?»

Мови називати не обов'язково: тоді Claude покаже розділи, де є стаття, і запропонує кілька.
За замовчуванням береться вікно за останні два роки; напишіть «з 2024-01-01» або «за
останній рік», щоб його змінити.

### Що означає відповідь

| У відповіді | Означає |
|---|---|
| growing, declining (зростає, спадає) | Стійкий тренд протягом усього вікна, з темпом за рік. Єдиний вердикт, що означає динаміку. |
| stable (стабільно) | Зміна за рік у межах ±5%. |
| no detectable trend (тренду не виявлено) | Нічого вимірного; відповідь каже, яку зміну було б помітно. |
| jumped, dropped (стрибок рівня) | Разовий стрибок, наприклад після перейменування чи посилання з головної сторінки. Це не зростання. |
| came from spikes (через сплески) | Зростання чи спад дали кілька коротких новинних сплесків; без них тренду немає. |
| not enough data, renamed (замало даних, перейменовано) | Замало трафіку або розірваний ряд. Інструмент відмовляється, а не вгадує; це не означає, що тема непопулярна. |
| high, medium, low (довіра) | Наскільки вірити вердикту. Кожна слабкість (коротке вікно, сильна сезонність, ...) знижує її на крок. |

«Увага» тут означає частку статті серед усіх переглядів її мовного розділу (переглядів на
мільйон), тож великі й малі мови можна чесно порівнювати.

## Як це працює

```
topic ─► resolve ─► fetch ─► reindex ─► gates ─► normalize ─► spikes ─► seasonality
          (search +   (SQLite   (NaN for   (11 checks,  (per million  (15-day robust z,
          Wikidata)   cache)    gaps)      refuse early) edition views) events + tails)
      ─► weekly medians ─► trend ×2 (with / without spikes) ─► change point ─► verdict
                          Theil-Sen + Mann-Kendall            Pettitt + step model
      ─► charts + one-page PDF + one JSON line
```

Найважливіші рішення:

- **Назви статей ніколи не будуються з того, що ввів користувач.** API переглядів не робить
  першу літеру великою: `astronomy` повертає приблизно 1/1000 переглядів `Astronomy`, і
  при цьому HTTP 200. Назви беруться з пошуку та міжмовних посилань Wikidata.
- **Частка, а не сирі перегляди.** Перегляди статті діляться на всі перегляди її розділу
  (згладжені 7-денною медіаною). Якщо сирі перегляди ростуть лише тому, що виріс увесь
  розділ, зростання інтересу не заявляється; якщо сирі перегляди стоять, а розділ
  скорочується, тема здобула частку. Порівнювати між мовами можна лише частку.
- **Тижневі медіани.** Щоденні перегляди автокорельовані (0,5-0,9); на щоденних точках
  рівний ряд виглядає як «значуще зростання». Тижневі медіани прибирають тижневий цикл і
  наближають вибірку до її ефективного розміру.
- **Тренд рахується двічі**, зі сплесками і без них. Зростання, яке зникає без сплесків,
  подається як спричинене подіями, а не як зростання.
- **Стрибки не є зростанням.** Стрибок після перейменування, посилання з головної сторінки
  чи зміни в пошуковику подається як зсув рівня, без річного темпу.
- **Перевірки якості йдуть до будь-яких оцінок.** Ряд із замалим трафіком, коротким вікном,
  довгими пропусками чи обвалом, що вказує на перейменування, отримує відмову, а не число з
  низькою довірою. Мова з відмовою показується окремо й ніколи не ставиться останньою.
- **Жодного балу.** Закритий словник вердиктів плюс довіра high/medium/low, яка знижується
  на крок за кожну слабкість (коротке вікно, автокореляція, сезонність, ...). Нульовий
  результат подається з мінімальним виявним ефектом: «тренду не виявлено; зміни понад
  ±9%/рік було б помітно».
- **Мови ранжуються ярусами** за часткою уваги, з довірчими інтервалами; мови, що
  перекриваються, ділять ярус замість хибних місць 1/2/3.

Формули, пороги, розібрані приклади та всі відхилення від початкового задуму:
[`references/methodology.md`](skills/wikipedia-interest/references/methodology.md).

### Стек

Python 3.12, `numpy`, `matplotlib` (бекенд Agg, PDF через `PdfPages`, DejaVu Sans з
matplotlib плюс резервні шрифти в `assets/fonts` для CJK, індійських, тайської та інших
писемностей, щоб назви статей виглядали однаково на будь-якій машині), `httpx`; `sqlite3`,
`argparse`, `math.erfc` зі стандартної бібліотеки.
Відкинуто: plotly+kaleido (потрібен системний Chrome), reportlab (вбудований шрифт не має
кирилиці й мовчки малює квадратики), fpdf2 (падає на першій кириличній літері), SVG
вручну (без cairo немає шляху з SVG у PDF), scipy (кожен тест вміщується в кілька рядків
numpy).

### Ефективність для повторних запитань

API Wikimedia на практиці дозволяє близько 10 запитів на хвилину з однієї IP-адреси.
Типове запитання коштує 8 запитів (пошук, міжмовні посилання, три статті, три підсумки
розділів). Кеш SQLite пам'ятає, які діапазони вже запитувалися, ніколи не завантажує
усталені дні повторно й раз на добу оновлює останні три дні. Те саме запитання вдруге
коштує 0 запитів; «а тепер те саме чеською» коштує 2. Папки з результатами названі за
запитом, а не за часом, тож повторний запуск перезаписує, а не накопичує.

## Як перевірено роботу ШІ

Код написано з допомогою ШІ. Нічого нижче не приймається на слово моделі.

**Тести з відомою відповіддю (169, `make test`).** Приклади, пораховані вручну, фіксують
кожну формулу: Манна-Кендалла на `[1, 3, 2, 1]` має дати `S = −1`, `Var(S) = 7.667`,
`Z = 0` (8.667 означає, що бракує поправки на однакові значення, −0.361 означає, що бракує
поправки на неперервність); Петтітт на `[1, 2, 3, 10, 11, 12]` має розділити ряд на
індексі 3 з `p = 0.291`. Синтетичні ряди із закладеною відповіддю: +30%/рік відновлюється
з точністю ±2 пункти, рівний ряд дає рівномірно розподілені p-значення (2-8% нижче 0,05 на
400 запусках), ряд із новинними сплесками визнається спричиненим подіями, стрибок визнається
зсувом рівня, сезонний цикл ±35% дає щонайбільше 3 хибні тривоги на 20 зерен. Кожна
перевірка якості спрацьовує на своєму прикладі й не спрацьовує на сусідньому. Кожне
речення, яке пише інструмент, проходить перевірку на заборонені твердження.

**Тести знайшли справжні вади задуму.** Чотири частини початкового задуму не пройшли своїх
синтетичних тестів і були змінені (подробиці в methodology.md): центроване 15-денне вікно
для сплесків пропускало новинний сплеск у 41 раз, чий спад заповнював пів вікна; дні +30%
на популярних статтях проходили як сплески; прямолінійне усунення тренду переносило
стрибки рівня в місячні зсуви (хибних сезонних трендів після виправлення стало 7,5% замість
27%); а мінімальний виявний ефект падав до 0 на малих числах. Окремо контрактний тест
зловив рядки stdout понад 1 КБ із шістьма мовами та довгими шляхами.

**Рендеринг без погляду.** Попередження про відсутній гліф вважається помилкою (перевірено,
що воно спрацьовує на тибетській, єдиній перевіреній писемності, якої немає в жодному
вбудованому шрифті); PDF має рівно одну сторінку A4, без дати створення, і `Вікіпедія`,
`Łódź`, `Řehoř`, `天文学`, `천문학`, `ดาราศาสตร์` видобуваються назад як текст; дві збірки
побайтово однакові; PNG не порожні. CI також проганяє тести в `python:3.12-slim`, де
шрифтів немає зовсім.

**Повний сценарій на Claude Haiku 4.5.** У `evals/` лежать п'ять випадків для
`claude plugin eval` на синтетичних даних (закладені відповіді: uk зростає ~23%/рік; pl
стабільна, а fr має разовий стрибок; de зростає лише через шість сплесків; cs має замало
даних; запитання про Google Analytics не повинно запускати навичку) і один живий випадок.
Самому харнесу потрібна shell-пісочниця, якої не було в контейнері збірки, тому кожен
випадок запускався на `claude-haiku-4-5` через `claude -p --plugin-dir` (той самий цикл
агента без харнесу), тричі після останньої зміни навички, без налаштувань, навичок і
MCP-серверів користувача та з порожнім кешем на кожен запуск, а відповіді оцінював за
рубриками окремий суддя Sonnet:

| Метрика (SPEC §11.3) | Ціль | Виміряно на Haiku 4.5 |
|---|---|---|
| Навичка спрацьовує на природних формулюваннях (6 запитів ×3, uk/en) | ≥ 90% | 18/18 (100%) |
| Хибні спрацювання на схожих, але чужих запитаннях (5 запитів ×3) | 0% | 0/15 |
| Викликів інструментів на сценарій | ≤ 8, медіана ≤ 5 | 2 у кожному запуску (Skill + один `compare`) |
| Повторні читання файлів | 0 | 0 |
| PDF записано в папку користувача | кожен сценарій | 12/12 |
| Піковий контекст | ≤ 60K токенів | 33,6-34,4K |
| Час | ≤ 60 с | 15-28 с |
| Вартість сценарію | ≤ $0,02 | $0,036-0,043 (не досягнуто: запитання, яке навичку не використовує, уже коштує $0,020, це власний промпт Claude Code) |
| Відповіді, що проходять рубрику (суддя Sonnet) | оцінка ≥ 0,8 | 14/15 |

Дійти до цього вдалося за кілька раундів, і найкорисніше в них саме промахи:

1. Перші запуски: агент робив `cd` у папку навички й писав звіти туди, не називав жодного
   обмеження, відповідав «Так, але…» на зростання зі сплесків і читав «замало даних» як
   «низький пріоритет». Виправлено правилом повного шляху, полем `caveat` у JSON, яке можна
   цитувати, і точними формулюваннями для кожного вердикту в `SKILL.md`. Наступний раунд:
   15/15.
2. Після виправлень за рев'ю повторний запуск набрав 12/15: двічі відмова для чеської
   перетворилася на «тема непопулярна», раз єдиним названим обмеженням були «синтетичні
   дані». Тексту в `SKILL.md` не вистачило, тож тепер рамку несуть самі дані: відмова йде з
   полем `reason`, яке каже, що малий трафік однієї статті нічого не каже про інтерес до
   теми, а шаблон відповіді має фіксований рядок «Limitations:».
3. Запит без назв мов («у вибраних розділах») запустив навичку 0 разів із 3: Haiku спершу
   питав, які мови. Тепер опис каже використовувати навичку все одно, бо вона сама може
   перелічити розділи. У фінальному повторному прогоні вона спрацювала на цей запит 3
   рази з 3.
4. Два запити, під які навичку ніколи не налаштовували (якою мовою локалізувати курс;
   запитання без назв мов), виявили ваду інструмента, а не моделі: біля межі 1 КБ рядок
   скидав `reason` відмови й розмір аудиторії раніше за шляхи до графіків, які агент ніколи
   не відкриває. Haiku заповнював прогалину, називаючи частку уваги «абсолютними»
   переглядами, а разовий стрибок «зростанням попиту»; до того ж `SKILL.md` казав читати
   кожен вердикт як динаміку. Тепер шляхи скидаються першими, а динамікою вважається лише
   тренд. Після цього кожна чеська відмова казала, що малий трафік нічого не каже про
   інтерес, і жодна з 5 відповідей про локалізацію не назвала стрибок зростанням чи попитом.
5. Фінальний повторний прогін, де кожен запит був українською або англійською, пройшов 14
   з 15 рубрик. Промах: відповідь українською почала опис разового стрибка у французькій
   словами «переглядання зростали» і лише потім назвала його разовою зміною, а не стійким
   зростанням; суддя не зарахував її через слово «зростання».

**Незалежне рев'ю коду.** Окремий агент перевіряв пакет на помилки коректності й мав
відтворити кожну знахідку пробним скриптом, перш ніж про неї повідомити. Він знайшов 11;
десять виправлено, кожна з регресійним тестом у `tests/test_regressions.py`. Найсерйозніша:
`log1p` від переглядів на мільйон, які часто менші за 1, сплющував темпи зростання
(+30%/рік читалося як +9%, стрибок на 60% як 17%); тепер зсув логарифма відносний до
ряду. Інші: падіння звіту з 14 і більше мовами, рядки помилок, які могли втратити
підказку, розмір стрибка там, де можна лише напрямок, подвійний підрахунок, коли
перейменована стаття поєднується з її перенаправленнями, дата стрибка на кілька днів
пізніше, мовчазний перехід на сирі перегляди, відносні шляхи кешу й перезаписаний підпис
панелі. Одинадцята, `--help` у stderr замість JSON, так задумано. Окремо погляд на
згенерований звіт виявив стрибок, датований на вісім тижнів пізніше: розділ Петтітта
зміщується, коли рівень після стрибка продовжує рости, тож тепер місце стрибка береться з
медіанного сканування.

**Живі дані на Claude Haiku 4.5.** На машині з доступом до мережі конвеєр працював із
живим API Wikimedia; `compare` на шість мов без кешу тривав 84 с. Шість запитів (три із
завдання, запитання про локалізацію і два схожі, але чужі, про Google Analytics і Google
Trends) пішли агентам Haiku 4.5, які, як і в Claude Code, бачили лише назву й опис
навички. `claude plugin eval` відмовився працювати на цьому Mac: Docker Desktop тримає
символьні посилання в `~/.docker`, і харнес не запускає Bash-пісочницю, яку не може
відгородити від цього сховища облікових даних. Тому судді Sonnet немає: кожну відповідь
звірено вручну з рядком JSON, який надрукував інструмент. Перший раунд запустив навичку на
4/4 запитах і 0/2 чужих, дві з чотирьох відповідей пройшли, а живі звіти виявили вади, яких
синтетичні дані показати не могли:

1. Японські, китайські, корейські, тайські та індійські назви виходили порожніми
   квадратиками: використовувався лише DejaVu Sans. Резервні шрифти (Noto, Droid Sans
   Fallback, Nanum Gothic; 7,6 МБ, OFL і Apache-2.0) тепер лежать в `assets/fonts` із
   зафіксованими джерелами; назва писемністю, якої не покриває жоден із них, наприклад
   тибетською, замінюється на «(see metrics.json)».
2. Із шістьма мовами заголовок PDF перелічував кожну статтю й вилазив за сторінку, а запуск
   із `--titles` називався за назвою, що першою йшла за алфавітом. Тепер заголовок називає
   тему й обрізається за шириною сторінки; запуск називається за назвою мовою джерела.
3. Із шістьма мовами й довгим шляхом рядок stdout скидав `tiers` раніше за темпи, і
   відповідь втрачала ранжування. Тепер ранжування ніколи не скидається.
4. Спад читався як «fell ~-12%/yr» (подвійний знак).
5. Відповідь про локалізацію радила «англомовну аудиторію», яку ніхто не вимірював. Тепер
   `SKILL.md` обмежує рекомендації проаналізованими мовами.

Кожне виправлення коду має регресійний тест. У другому раунді навичка знову спрацювала на
4/4 і 0/2; відповідь про локалізацію трималася німецької, французької й польської, кожне
число збігалося з рядком JSON, а звіт з японськими й кириличними назвами відрендерився.
Дві відповіді ще недотягували: одна навела цифру довіри («не більше 20%»), якої
інструмент ніколи не давав, а порівняння п'яти розділів перелічило кожен тренд, але не
сказало, який розділ отримує найбільше уваги, хоча `tiers` уже був у рядку.

Тепер `SKILL.md` забороняє будь-яке число, якого немає в рядку, і просить одне речення про
порядок у `tiers`. У третьому раунді на запитання про довіру відповіли лише рівнем довіри
та його чотирма прапорцями, а два порівняння шести й семи розділів правильно назвали
порядок. Проте обидва всупереч інструкціям відкрили `metrics.json`, щоб дістати числа,
які рядок обрізав (шлях до папки агентів мав 250 символів, а це залишає мало місця в
1 КБ), і одне процитувало всі дванадцять обмежень замість `caveat`. З ще одним правилом,
«якщо поля немає в рядку, пропусти його», два повторні запуски того самого запиту
українською зі шляху довжиною 263 символи зробили по три виклики інструментів і жодного
разу не відкрили `metrics.json`. Один порівняв п'ять розділів, назвав порядок uk, pt, далі
pl і ja нарівні, далі de, точно як у `tiers`, збігся в кожному числі й навів лише `caveat`
(33 с, $0,048). Другий вибрав шість розділів, з яких достатній трафік мала лише англійська,
тож порядку, який можна назвати, не було. Його числа збіглися, але він скоротив шлях до
звіту до `/out/…`, якого не існує, і сказав, що розділи з малим трафіком «можуть вказувати
на меншу популярність», від чого застерігає `reason` відмови (88 с без кешу, $0,053).

**Сам Claude Code, зі свіжого клону.** Харнес і запуски з `--plugin-dir` завантажують
навичку напряму, тож остання перевірка йшла через справжній CLI `claude` на Haiku 4.5, де
модель бачить лише опис навички. Попередній опис, який ще не казав, що навичка сама
завантажує дані й замінює пошук в інтернеті, спрацював на трьох українських запитах з
`evals/` так само часто, як нинішній, 9 з 9 кожен, тож виміряного виграшу від переписаного
опису там немає. Нинішній спрацював на 18 з 18 запитів і на 0 з 15 схожих, але чужих;
запитання тривало 8-20 с і коштувало $0,034-0,043. Далі копії репозиторію без
встановленого плагіна відкрили так, як це зробив би новий користувач, і попросили
підтягнути перегляди Вікіпедії про астрономію українською й польською за два роки. З
посиланням у `.claude/skills/` і `CLAUDE.md` Haiku використав навичку в 4 з 4 запусків.
Кожна копія стартувала без залежностей: CLI повідомив, що бракує Python 3.12, і надрукував
команду встановлення, Haiku виконав її, повторив виклик і відповів за 40-48 с за
$0,053-0,054, кожне число збіглося з рядком JSON. Три запитання українською отримали
відповіді українською, а одне англійською отримало відповідь англійською, хоча дані були
з українського й польського розділів; раніше одна відповідь пішла за мовою даних, тому
`SKILL.md` каже відповідати мовою користувача. Українська в Haiku грубша за англійську
(наприклад, «артикул» замість «стаття»), але числа трималися. Без посилання й `CLAUDE.md`
вийшло 1 з 2: раз Haiku сам знайшов `skills/wikipedia-interest/SKILL.md` і виконав його,
а раз вручну завантажив помісячні перегляди й повідомив про падіння «-81%» для «України»
від вересневого піку та стабільну «Польщу», тоді як навичка знайшла спад в обох розділах
із низькою довірою. `resolve` теми з довгими назвами у 20 розділах друкував порожній рядок, бо
назви не вміщалися в 1 КБ; тепер замість цього відкидаються найменші розділи.

### Запуск evals

```bash
cd skills/wikipedia-interest
UV_LINK_MODE=copy uv sync --locked          # the harness rejects hard-linked files
claude plugin eval . --tag fixture --allow-tools Bash --trust-plugin \
  --model claude-haiku-4-5 --judge-model claude-sonnet-5 --runs 3
claude plugin eval . --tag live --allow-tools Bash --trust-plugin --model claude-haiku-4-5
```

Харнесу потрібна його shell-пісочниця (bubblewrap і socat на Linux). Випадки на
синтетичних даних задають `EVAL_WIKITRENDS_FIXTURE=demo`, тож агент запускає справжній
CLI на синтетичних даних з відомою відповіддю. `evals/trigger-*.md` містять запити для
перевірки спрацювання.

## Чого навичка не робить

- Не прогнозує: навичка описує спостережене вікно й ніколи не екстраполює.
- Не вимірює попит чи намір купити: перегляди лише наближено показують увагу.
- Не в реальному часі: дані запізнюються на один-два дні.
- Не перевіряє тисячі тем за раз у v1 (див. план розвитку).

Дванадцять обмежень, які друкуються в кожному звіті, наведено в
[`assets/report-template.md`](skills/wikipedia-interest/assets/report-template.md).

## План розвитку

1. **Від статті до теми.** Інтерес розподілений між багатьма статтями й перенаправленнями.
   Будувати тему як версійований набір статей (категорії Wikidata, `prop=redirects`) і
   підсумовувати їхні ряди. `--include-redirects` є першим кроком.
2. **Масштаб.** SQLite замінити на Parquet/DuckDB, пакетний режим для сотень тем,
   початкове заповнення з [дампів переглядів](https://dumps.wikimedia.org/other/pageviews/)
   замість API, паралельні запити в межах ліміту.
3. **Більше сигналів.** Унікальні пристрої як друга думка; перегляди за країнами, щоб
   відрізнити «інтерес у країні» від «інтересу мовою», а для локалізації це різні речі;
   зовнішні джерела (Google Trends, магазини застосунків) як перехресна перевірка, а не
   заміна.
4. **Перевірити висновки.** Бектест: узяти те, що навичка порадила б два роки тому, і
   порівняти з тим, що сталося. Лише так можна дізнатися, чи передбачає зростання
   переглядів справжній попит; сьогодні це припущення.

```

AGENTS.md                         те саме для Codex та інших агентів

  SKILL.md                        інструкції для агента (10 КБ, менше 3K токенів)

```
